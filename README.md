# Motorsport Hub

iPhone home-screen motorsport widget for Scriptable.

## Current status
- Current development line: **12-category hardening / Release Candidate preparation**.
- Categories: **12 + QA diagnostics**.
- Direct Router architecture: one selected category → one category module.
- Automated render smoke: **12 × Small/Medium = 24 cases**.
- Immutable release packaging: **implemented**.
- Build-time Hero provenance / subject-aware crop / quality gates: **implemented**.
- Public release / `main` merge: **not performed**. Explicit owner approval is required.

The canonical development branch is `hardening/v9.3-codex-handoff` until the final audit and release process are complete. `main` is intentionally not the current hardening source yet.

## Canonical Scriptable loader
### Public/release distribution
**Use only `scriptable-loader-v6.js` generated by CI from the exact immutable release commit.**

The generated v6 loader embeds:
- one fixed 40-character Git commit SHA;
- Router byte length + SHA-256;
- SHA-256 + byte length for every one of the 12 category modules and QA;
- release-namespaced Candidate / LKG / quarantine storage;
- exact 12-category Router manifest.

It is produced by:
`tools/generate-release-package.mjs`

and is uploaded with `release-integrity.json` as a GitHub Actions release artifact.

### Repository loader files
- `scriptable-loader.js` — **legacy v4 compatibility loader**, not the canonical immutable release distribution.
- `scriptable-loader-v5.js` — **legacy transactional compatibility loader**; supports the 12-category manifest but does not pin the complete release by SHA-256.
- `scriptable-loader-v6-qa.js` — **retired historical QA snapshot**. It intentionally refuses to run the old fixed package.
- `scriptable-loader-hardening-v5.js` — hardening/device-test utility only.
- `scriptable-loader-v6.js` — generated output; only the version generated from the exact approved release SHA is canonical.

Do not copy an old static v6 loader from another commit or test session.

## Architecture

```text
Scriptable immutable Loader v6
        ↓
Motorsport Hub Router
        ↓
exactly one selected category module
        ↓
data/cache + approved Hero
        ↓
Small / Medium Widget
```

Current architecture deliberately avoids:
- the historical serial reliability-wrapper waterfall;
- Router-time source rewriting;
- silent fallback from an invalid widget parameter to F1;
- accepting unverified immutable-release code.

All 12 category data caches use schema version 1.

### Hardening vs final release source
The hardening Router intentionally defaults to `hardening-live` for direct device testing so it cannot silently read stale modules from `main`.

**That hardening default is not a production setting.**
Before a final merge, `tools/prepare-main-release.mjs` transforms the release branch Router default to `main` and sets final Registry release states. The transformation is CI-tested in dry-run and simulated release modes before it may be used.

## Widget information model
Circuit-racing categories generally use:
- Small: next event / countdown / venue;
- Medium: next event / countdown / top three / points.

Dakar deliberately uses a rally-raid hierarchy:
- Small: next stage / countdown / stage / SS distance / route;
- Medium: stage information + overall CAR top three / GAP.

## Hero / licensing pipeline
All runtime Hero assets must be represented in `hero-assets.json` and `ATTRIBUTION.md`.

The hardening line includes build-time tools for:
- approved-source provenance and licensing;
- Wikimedia candidate discovery;
- HTTP / MIME / actual image-dimension checks;
- subject detection;
- `IDENTITY`, `ACTION`, `ENVIRONMENT` roles;
- Small / Medium subject-aware crop generation;
- text-safe / veil-aware checks;
- horizontal-car balanced Small crops;
- scoped fallback handling;
- LKG/rejection behavior;
- visual-regression artifacts.

Image ML runs at build/CI time, **not inside Scriptable runtime**.

Notable corrected Hero paths include current action-oriented assets for F1, SUPER GT and D1GP, plus accepted crop/fallback hardening for WEC, WRC, MotoGP, FDJ and Dakar.

## Release process
1. Finish the final hostile code/architecture audit on `hardening/v9.3-codex-handoff`.
2. Return Hardening CI and Release Readiness to green after any fixes.
3. Generate the exact final immutable 12-category package.
4. Perform one consolidated iPhone check on that package: online Candidate, routing sanity, fully-offline verified LKG and obvious visual regression check.
5. Obtain explicit owner approval.
6. Create a dedicated `release/*` branch.
7. Run the guarded main-release finalizer on that release branch only.
8. Require transformed release CI to pass and generate the production immutable artifact.
9. Merge to `main` only after those gates pass.

No Store submission, public distribution, deployment or `main` merge is authorized merely because automated gates are green.
