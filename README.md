# Motorsport Hub

iPhone home-screen motorsport widget for Scriptable.

## Current status
- Production baseline: **v9.5.3** on `main`.
- Production release commit: `afa07784d6de7b038f0f4ba802bd1b708f95488d`.
- Categories: **12 + QA diagnostics**.
- Direct Router architecture: one selected category → one category module.
- Automated render smoke: **12 × Small/Medium = 24 cases**.
- Immutable release packaging: **implemented and production-validated**.
- Hero Channel: CI-gated `hero-live` delivery with device LKG + embedded Hero fallback.
- Post-release improvements are developed outside `main` and require a new validated release cycle before merge.

`main` is the canonical released baseline. Development/hardening branches must never be treated as production merely because their CI is green.

## Canonical Scriptable loader
### Production distribution
**Use only `scriptable-loader-v6.js` generated by CI from the exact immutable release commit.**

Production users install only that CI-generated `scriptable-loader-v6.js` from the exact approved release SHA.

The generated v6 loader embeds:
- one fixed 40-character Git commit SHA;
- Router byte length + SHA-256;
- SHA-256 + byte length for every one of the 12 category modules and QA;
- release-namespaced Candidate / LKG / quarantine storage;
- exact 12-category Router manifest;
- bounded local-only operational telemetry when enabled by the release generator.

It is produced by `tools/generate-release-package.mjs` and uploaded with `release-integrity.json` as a GitHub Actions release artifact.

### Loader policy
- `scriptable-loader-v6.js` — **the only production distribution loader** when generated from the exact approved release SHA.
- `scriptable-loader-hardening-v5.js` — development/device-test utility only.
- `scriptable-loader.js` — **legacy v4 compatibility loader**; not a production distribution path.
- `scriptable-loader-v5.js` — **legacy transactional compatibility loader**; not a production distribution path.
- `scriptable-loader-v6-qa.js` — **retired historical QA snapshot**; it must not be distributed.

Do not distribute hardening, QA, legacy, or arbitrary static v6 copies to production users.

## Architecture

```text
Scriptable immutable Loader v6
        ↓
Motorsport Hub Router
        ↓
exactly one selected category module
        ↓
data/cache + Hero Channel/LKG/embedded Hero
        ↓
Small / Medium Widget
```

Current architecture deliberately avoids:
- the historical serial reliability-wrapper waterfall;
- Router-time source rewriting;
- silent fallback from an invalid widget parameter to F1;
- accepting unverified immutable-release code.

All 12 category data caches use schema version 1.

## Hero / licensing pipeline
Hero publication is quality-gated. A newer image is not automatically better and must not replace the current LKG merely because it is newer.

The pipeline covers:
- approved-source provenance and licensing;
- Wikimedia candidate discovery;
- HTTP / MIME / actual image-dimension checks;
- category/context integrity;
- subject detection;
- `IDENTITY`, `ACTION`, `ENVIRONMENT` roles;
- Small / Medium subject-aware crop generation;
- text-safe / veil-aware checks;
- minimum quality improvement over Hero LKG before promotion;
- device Hero Channel LKG fallback;
- embedded module Hero as the final fallback.

Image ML runs at build/CI time, not inside Scriptable runtime.

## Release process
1. Develop changes on a non-`main` branch.
2. Return deterministic CI / release readiness to green.
3. Create a dedicated `release/*` branch.
4. Generate the exact immutable release package.
5. Perform one consolidated iPhone check: online Candidate, routing sanity, fully-offline verified LKG, and obvious visual regression check.
6. Obtain explicit owner approval.
7. Run the guarded production finalizer on the release branch only.
8. Require transformed release CI to pass and generate the production immutable artifact.
9. Merge to `main` only after those gates pass.

Rollback and hotfix procedure is defined in `ROLLBACK_HOTFIX.md`. No Store submission, external deployment, paid service activation, or other irreversible/public action is authorized merely because automated gates are green.
